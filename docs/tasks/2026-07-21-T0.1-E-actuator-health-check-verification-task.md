# 2026-07-21 任务：T0.1-E Actuator 健康检查验证

## 1. 任务目标

使用 Spring Boot Actuator 提供 Stackora 的标准健康检查，而不重复实现自定义健康检查 Controller。

## 2. 用户价值

开发者和部署环境可以使用 Spring Boot 的标准运维端点判断应用状态，并在数据源已配置时获得数据库健康状态。

## 3. 实现范围

- 保留 `spring-boot-starter-actuator` 依赖。
- 通过 `management.endpoints.web.exposure.include=health,info` 暴露 `health` 和 `info`。
- 保持 `management.endpoint.health.show-details=when-authorized`，避免向未授权调用方暴露健康细节。
- 使用标准 `GET /actuator/health`，不创建 `/api/health`、自定义 Mapper 或自定义 Service。
- 在开发环境数据源可用时，验证 Actuator 的数据库健康贡献者参与聚合状态。

## 4. 验收标准

- 应用启动后，`GET /actuator/health` 返回健康状态。
- `GET /actuator/info` 可访问。
- 数据库配置正确时，健康检查聚合状态反映数据源可用性。
- 数据库不可用时，接口不报告虚假的 `UP`。
- 对未授权调用方不暴露健康细节。
- 至少保留一条可重复执行的 Actuator 端点测试或记录一次真实本地验证命令与结果。

## 5. 不做内容

不实现自定义健康检查 Controller、Service、Mapper、响应对象或业务表；不引入新的监控平台、Redis、消息队列或 Testcontainers。

## 6. 涉及文件

- `pom.xml`
- `src/main/resources/application.yaml`
- `src/main/resources/application-dev.yml`
- `src/test/java/`（新增 Actuator 验证测试时）
